# CORE — áp dụng cho code/config/test mới hoặc được sửa

Nhãn áp dụng theo [delivery-gates.md](../delivery-gates.md); chỉ chặn khi MUST đúng phạm vi và gate đã kích hoạt.

- **CORE-01 MUST [ALWAYS] — Phạm vi:** làm đúng acceptance criteria; giữ thay đổi ngoài task của người khác. Không tự thêm cloud, installer, chuyển đổi code hay gọi AI có phí vào task CRUD.
- **CORE-02 MUST [ALWAYS] — Ngôn ngữ:** TypeScript strict, ESM; tên code/API bằng tiếng Anh, tài liệu hướng dẫn bằng tiếng Việt. Không dùng `any`, `@ts-ignore` hoặc assertion để che dữ liệu chưa validate; boundary không tin cậy dùng `unknown` rồi kiểm tra.
- **CORE-03 SHOULD [ALWAYS] — Naming:** file `kebab-case`, React component/type `PascalCase`, function/biến `camelCase`, hằng cấu hình cố định `UPPER_SNAKE_CASE`. Suffix theo trách nhiệm: `.routes.ts`, `.service.ts`, `.repository.ts`, `.schema.ts`, `.runner.ts`, `.test.ts`. Generated/vendor file theo tool sinh, không sửa tay.
- **CORE-04 MUST [ALWAYS] — Ranh giới:** route → service → repository/port; UI chỉ gọi API. Không import database/process vào route hoặc UI; không import Fastify vào service. Dependency được truyền tường minh tại composition root.
- **CORE-05 SHOULD [ALWAYS] — Độ đơn giản:** dùng named export; function có một trách nhiệm; chỉ tạo abstraction khi có ranh giới thật. Không tạo generic base service/repository, global service locator hoặc thư mục `utils` để chứa logic chưa phân loại. Ngoại lệ export do framework/tool yêu cầu được phép.
- **CORE-06 MUST [ALWAYS] — Dependency/config:** một package manager npm và lockfile root. Khóa runtime/phiên bản đã kiểm chứng lúc init; env đọc và validate trong config, không rải `process.env` trong feature. Không commit credential, database, log, artifact thật hoặc source khách hàng vào repo sản phẩm.
- **CORE-07 MUST [ALWAYS] — Lỗi và async:** không nuốt lỗi, không trả thành công khi side effect thất bại. Await hoặc đăng ký lifecycle rõ ràng cho async task; hủy timer/listener/stream khi kết thúc. Không log hai lần cùng lỗi ở mọi lớp.
- **CORE-08 MUST [ALWAYS] — Tính kiểm chứng:** không ghi “test pass”, “review pass”, “đã hỗ trợ Windows” khi chưa có bằng chứng. Mọi giả định/giới hạn còn ảnh hưởng task phải được nêu; code và tài liệu không mô tả feature chưa tồn tại như đã hoàn thành.
- **CORE-09 MUST [ALWAYS] — Độc lập thương hiệu:** code sản phẩm, package/import, biến môi trường, API/schema, database, storage key/path, log/error và fixture/test dùng tên nghiệp vụ hoặc tên sản phẩm trung lập; không gắn cứng tên công ty phát triển/khách hàng. Baseline: `PORTAL_*`, `@portal/*`, data directory `MigrationPortal/portal-dev`, temp prefix `portal-*`. Khi có UI/export, tên hiển thị/logo/màu/thông tin công ty lấy từ cấu hình branding/asset/template tách biệt; đổi branding không đổi định danh kỹ thuật, DB/path hoặc nhánh nghiệp vụ. Không tự xây multi-tenant, licensing hay framework white-label cho task nhỏ. Đổi tên đã được sử dụng phải nêu ảnh hưởng env/package/data path và cách giữ dữ liệu, không tự di chuyển/xóa DB.

- **CORE-10 MUST [ALWAYS] — Đa nền tảng:** Portal hướng tới Windows/macOS/Linux. Code/config/scripts mới hoặc đang sửa không mặc định OS của Dev là OS duy nhất; logic nghiệp vụ độc lập OS, khác biệt path/process/storage nằm ở config hoặc adapter phù hợp. Dùng API filesystem/path thay shell-specific command khi có thể. Khi task chạm native/process/path, đọc [platform-support](../platform-support.md), ghi OS/CPU/runtime đã kiểm và chưa kiểm; mock không thay native smoke. Không tự làm installer/CI/framework desktop ngoài task và không tuyên bố hỗ trợ OS chưa được kiểm chứng.

Phạm vi CORE-09 là source/config/test đang thêm hoặc sửa. Tên vendor/library/protocol cần để tích hợp (Fastify, SQLite, Claude), legal attribution và dữ liệu do người dùng nhập không phải branding gắn cứng. Proposal, lịch sử dự án và nội dung kinh doanh được phép mang tên công ty; không tìm-thay toàn workspace. Tên gọi skill nội bộ hiện có được giữ để tương thích lệnh/liên kết, không dùng tên skill làm prefix trong sản phẩm.

Ví dụ áp dụng CORE-09: `PORTAL_PORT` và `portal-api-test-` phù hợp; `<company>_PORT` hoặc nhánh `if (brandName === '<company>')` trong service là vi phạm. UI đọc `branding.displayName`/`branding.logoUrl` từ cấu hình là phù hợp; logo riêng trong asset branding hoặc tên công ty trong proposal không bị báo lỗi chỉ vì có tên riêng. Khi chưa triển khai UI, chưa cần tạo module branding rỗng.

Ví dụ: thêm điều kiện “project chỉ có một run đang hoạt động” thuộc job service + ràng buộc DB, không chỉ disable nút trên UI. Tên file không đúng convention là lỗi nhỏ; chạy hai process AI do race có mức độ cao hơn dù file đặt tên đúng.

- **CORE-11 MUST [FEATURE:api,ui] — Nguồn policy:** giới hạn/default nghiệp vụ đang dùng chung giữa contract, service và UI phải có nguồn duy nhất hoặc dùng lại schema, không sao chép thuật toán validation. Thay giới hạn có ảnh hưởng storage cần migration mới và test tương thích; không sửa lịch sử migration. Literal protocol, catalog lỗi an toàn, fixture marker và copy UI một ngôn ngữ được phép nằm trong code ở tầng chịu trách nhiệm; không ép mọi literal thành env/config. Xem [mẫu policy và lỗi API](../patterns/api-errors-policy.md).
