# DATA — database, filesystem, evidence, review và export

Nhãn áp dụng theo [delivery-gates.md](../delivery-gates.md); chỉ chặn khi MUST đúng phạm vi và gate đã kích hoạt.

- **DATA-01 MUST [FEATURE:storage] — SQL:** SQL chỉ trong repository/migration; parameter hóa giá trị, allowlist tên cột/sort nếu động. Bật foreign keys cho connection, unique/index theo invariant; transaction ngắn. Map row sang domain/DTO, không trả DB row nội bộ trực tiếp qua API.
- **DATA-02 MUST [FEATURE:storage] — Migration:** file đánh số và schema version; migration đã phát hành không sửa nội dung. Khi thay schema đã có dữ liệu phải test nâng cấp và giữ dữ liệu; trước thay đổi dữ liệu thật có bản khôi phục nhất quán. Nếu triển khai backup/restore, không copy riêng .db khi WAL đang ghi. Init DB đầu tiên không phải test version chưa tồn tại; rule này không yêu cầu UI hoặc lịch backup tự động.
- **DATA-03 MUST [LIVE] — Path:** đăng ký root từ lựa chọn local rõ ràng; canonicalize và kiểm tra containment theo path segments và filesystem thực tế trên OS đích. Không mặc định case-insensitive hoặc lowercase toàn path. Kiểm symlink escape, Windows junction/reparse/drive/UNC policy, POSIX permission, traversal, Unicode và quyền truy cập theo [platform-support](../platform-support.md). Không dùng startsWith string làm kiểm tra duy nhất; revalidate trước đọc, không nhận arbitrary path qua API artifact.
- **DATA-04 MUST [FEATURE:analysis] — Snapshot/encoding:** theo [đặc tả đọc source](../specs/source-analysis.md), profile BSN chọn CP932 cho file không BOM, không đoán theo UTF-8. Chỉ snapshot text allowlist; binary không decode. Giữ raw bytes, manifest hash/encoding và normalized text bất biến; source đổi trong lúc copy báo lỗi. Không âm thầm dùng replacement character hoặc bỏ file lỗi khỏi thống kê coverage.
- **DATA-05 MUST [FEATURE:storage] — Artifact tối thiểu:** ID server sinh, ghi ngoài source gốc; temp → atomic rename cùng filesystem → commit metadata. Chỉ bản hoàn tất mới public. Khi crash, orphan không được trình bày là thành công; MS1 cho phép cô lập và xử lý thủ công có hướng dẫn. Không bắt buộc auto-cleanup; transaction SQL không rollback filesystem. Mọi cleanup chỉ nhắm file app sở hữu.
- **DATA-06 MUST [FEATURE:analysis] — Evidence:** theo line/quote/hash policy trong [source-analysis](../specs/source-analysis.md) và [BR/Design contract](../specs/understanding-contract.md). AI chỉ đề xuất path/dòng/quote; backend kiểm với snapshot và gắn hash/trạng thái kiểm chứng. Không có bằng chứng thì cần xác minh; quote khớp không tự chứng minh suy luận đúng.
- **DATA-07 MUST [FEATURE:reviews] — Review:** append-only approve/reject/comment gắn artifact ID + version + source hash + reviewer + thời gian UTC. Update có expected version; stale review trả 409. Không sửa lịch sử approval để phù hợp kết quả mới; approved rule chỉ áp dụng trong project và revision phù hợp. Danh tính reviewer local do người dùng nhập chưa tương đương xác thực tổ chức.
- **DATA-08 MUST [FEATURE:export,reviews] — Export/isolation:** truy vấn artifact/review theo project + run + version, kiểm tra ownership; không chọn latest ngầm. Export chứa schemaVersion, run/source version, trạng thái review, nhãn draft/demo và câu hỏi còn mở. Escape HTML/Markdown; không export token, full command, absolute path hay raw log nhạy cảm.
- **DATA-09 MUST [ALWAYS] — Dữ liệu vận hành:** data directory/config tách khỏi source và repo; fixture test/demo là dữ liệu sạch được phép chia sẻ. Không log source/prompt mặc định. Cleanup/retention không xóa artifact đang được review/tham chiếu; v1 không tự xóa lịch sử nếu chưa có policy rõ ràng.
- **DATA-10 SHOULD [LATER] — Tự động hóa vận hành:** lịch backup, UI restore và orphan cleanup theo retention chỉ làm khi có task riêng. Khi thực hiện vẫn phải tuân DATA-02/DATA-05/DATA-09; chưa có các tính năng này không chặn MS1.

Ví dụ: artifact v2 đã approve; chạy lại sinh v3 → v2 vẫn giữ lịch sử, v3 là draft. Đổi source làm evidence không khớp → cần review lại, không copy trạng thái approved từ run trước.
